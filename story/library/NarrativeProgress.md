# NARRATIVE PROGRESS — план внедрения сюжетных состояний
> **Технический проект, НЕ инструкция немедленно переписать Unity.** Все требования здесь должны быть реализованы позже отдельной веткой, после утверждения сценария. Текущие механики FishNet, HUD, доставка и аудио не затрагивались.

## Проверенная архитектура на исходной ветке develop
- `TeamProgressData`: `money`, `unlockedBoats`, `permanentItems`, `royalItems`, `unlockedUpgrades`, `collectedArtifacts`, `environmentVisits`. **Пока нет** полей `storyBeats`, показа кат-сцен и статистики успеха каждого острова.
- `TeamProgressManager`: сохраняет team JSON, умеет `RegisterArtifact`, `UnlockRoyalItem` и сетевые snapshots; новый narrative state нужно добавлять совместимо со старыми сейвами.
- `MissionDefinition`: `missionId`, `oceanDestination`, summary, difficulty, artifactCount и статические тексты. Текущие `Mission_01..05` — не полноценный сюжетный менеджер, часть чисел — прежние описания, не утверждённая работающая система «два из четырёх».
- `MajorEncounterZoneDirector`: сервер выбирает активные зоны с приоритетом ранее не посещённых. Есть событие `ZoneVisited` и текущая история зон, но это **не** автоматическая награда/подтверждение сюжетной миссии.
- `MissionExtractionPool` фиксирует награды и переносит артефакты/королевские предметы в командный прогресс после успеха. Не путать момент поднятия `Artifact` с доставкой.
- `OceanTransitJourney` владеет переходами HUB ↔ Ocean ↔ Island и обработкой провала в актуальных сценах; не заменять переходы старой прямой `SceneManager.LoadScene`.
- `HubNpcDialogueCatalog.TryGet` смотрит **path** в сцене; `HubNpcDialogueHud` показывает локальные страницы, а `HubUiClickAudio` подавляет лишние UI-звуки во время диалога.

## Предлагаемые данные (схема/псевдоконтракт)
Командный сейв:
```text
chapterProgress (1..4)
islandProgress[islandId] = {
  completedSuccessfulExpeditions: integer,
  collectedUniqueArtifactIds: set<string>,
  royalRelicDelivered: bool,
  optionalClueIds: set<string>
}
storyEventIdsSeen: set<string>  // серверные одноразовые последствия
unlockedNarrativeContracts: set<string>
```

Локальное сохранение пользователя/клиента:
```text
seenCinematics: set<C0|C1|C2|C3|C4>  // видел или явно пропустил
cinematicSubtitleSettings: language/size/etc (через общие настройки)
```

**Разделение критично:** завершение главы и разблокировка следующего острова — **серверный командный факт**. Просмотр или пропуск кат-сцены — **локальный выбор каждого участника**. Клиент без C1 не должен заблокировать остальным миссии, но должен иметь возможность воспроизвести ролик из журнала.

Флаги/IDs для Alpha (предложение):
```text
intro_ready
intro_played_local
island_01_first_return
island_01_royal_delivered
island_02_first_return
island_02_royal_delivered
island_03_first_return
island_03_royal_delivered
island_04_first_return
island_04_royal_delivered
island_05_first_return
island_05_royal_delivered
chapter_01_completed
chapter_01_cinematic_seen_local
```
Точные ID утвердить в одном enum/таблице, а не разносить по строковым условиям нескольких HUD. Не привязывать к порядку открытий необязательных подсказок. В будущих главах сохранять те же правила.

## Условия открытия / доставки
1. Каждая экспедиция должна иметь server-side устойчивый `runId`; `completedSuccessfulExpeditions` увеличивается **ровно один раз** за подтверждённый успешный возврат, не при повторной загрузке HUB или переподключении.
2. Собирать уникальные обычные артефакты по стабильным `artifactId`, не по видимому имени; показывать 4/4 и недостающие. В каждой отдельной поездке на данный остров назначаются два различных экземпляра/варианта, с приоритетом не найденных.
3. После достижения **4/4 + достаточное количество успешных заходов** становится доступной особая задача на королевскую реликвию (вариант: третий заход). Не блокировать соло.
4. Награда за королевскую реликвию и флаг `island_N_royal_delivered` записываются **только** при подтверждённой доставке/зачёте. Обработка идемпотентна, повторная доставка дубля не увеличивает счётчик и не открывает главу второй раз.
5. **C1:** `all(island_01..05.royalRelicDelivered) && !chapter_01_completed` → сервер ставит `chapter_01_completed`, сохраняет snapshot, раскрывает метаданные следующей главы; клиенты в HUB получают event `C1_Available`. Ролик **не является** источником записи сюжетного прогресса.
6. Первые пять реликвий **не** активируют древнюю систему на всех островах и не удаляются из командного сейва при просмотре C1.

## NPC-варианты без ломания текущих диалогов
**Не заменять `NpcDialogues.json` целиком.** Текущий JSON (62 записи) остаётся исходной бытовой речью.

Дополнительный слой, например отдельные `NpcNarrativeVariants` ScriptableObject/JSON:
```text
npcId                  // из записи HubNpcDialogueCatalog.Entry.id
minimumStoryBeat       // первый допустимый milestone
maximumStoryBeat?      // опционально
priority               // чтобы выбрать один слух, а не очередь из 10
lines[]                // 1–2 короткие необязательные текстовые страницы
oncePerProfile?        // для редких уникальных улик, не для бытовых приветствий
```

При обычном взаимодействии **сохраняется** `HubNpcDialogueHud` с текущим скроллом, Next/Close и коротким `PlayDialogueVoice`. Расширитель диалогов передаёт выбранные строки **для конкретного локального игрока**, не копируя `PathOf` как новый сюжетный ID. Если нет подходящего milestone — обычные три строки из ресурса. Предметы, NPC-модели, коллайдеры, HUD и голоса по-прежнему не модифицируются.

**Торговцы:** как специальный источник используют `RoyalMarketVendor.GreetingLines` / `MarketPlayerUI`, туда добавлять отдельную условную текстовую страницу при необходимости. Торговля и ранги остаются работоспособными при закрытии диалога. Переход на общий NPC HUD запрещён.

**Никаких новых оплаченных голосов обычным NPC.** Их текущие звуковые банки и ambient pool остаются источниками «неразборчивой речи», не синхронизируемой с буквальным текстом.

## Cutscene player — отдельная презентационная система
**Вход:**
- `C0` — новая локальная кампания/первый заход в HUB, без сетевой зависимости от чужого просмотра.
- `C1` — серверное событие завершённой главы I после безопасного возврата в HUB. Для C2, C3, C4 аналогично по окончании островов 10/15/20.

**Проигрывание:**
- Режиссёрский Timeline/камера + AudioClip VO + субтитры; использование экранной локальной презентации предпочтительнее манипуляции сетевыми player/boat/Artifact объектами.
- Вступительные кадры могут использовать `HUBTOWN_V2_REBUILT` и ocean visuals; никаких фактических live миссий/физических перемещений ради камеры.
- Уменьшить громкость игрового мира для конкретного слушателя, не посылать глобальные mute RPC всем игрокам.
- Во время voiced сцены подавить NPC mumbles и ambient в локальном миксе, затем гарантированно восстановить настройки и источники даже при `Skip`, disconnect, scene reload.
- Обязательны пропуск, субтитры, повтор из меню/журнала (в перспективе), восстановление управления/курсора. Способ пропуска в совместном игровом моменте должен быть индивидуальным, а не один зритель решает за всех.

**Сохранение:**
- сервер подтверждает сюжетную награду **до** показа C1; когда игрок закрывает/пропускает, только local `seenCinematics` помечается;
- late joiner получает authoritative snapshot и не переигрывает чужую историческую сцену по умолчанию. Может открыть её сам в журнале;
- не отправлять VO файлы через FishNet; они обычные локальные assets.

## Простая проверка после будущей реализации
Проверки делаем как обычный компактный QA pass, а не многочасовую новую тестовую инфраструктуру:
- новый соло-профиль: C0 один раз / skip → HUB → доска и NPC живы;
- существующий сейв после миграции: деньги, ранги, лодки и найденные предметы не потерялись;
- 4/4 и 3+ заезда без искусственного рандом-гейта, третья конфигурация уникальна;
- успешная доставка пятой реликвии: C1 ровно один раз, карта открылась, server state сохранился; повторная доставка/перезагрузка дубля не вызывает повтор;
- Host + Client: один смотрит C1, второй пропускает; оба могут двигаться/сохранять общий прогресс, HUD при разговоре с NPC строго локален;
- после любой кат-сцены: нет застрявшего mute/ducking, мусорных курсоров, потерянных input locks, пропавшего HUD;
- короткий smoke-run перехода HUB → Ocean → Island → Ocean → HUB на работающем пути FishNet.

## Минимальные стадии внедрения
1. Согласовать данный канон и чистовые C0/C1; никаких новых NPC для этого не требуется.
2. Сделать art/storyboard и записать два оплаченных голоса, только после утверждения текста.
3. Реализовать локальное cinematic presentation + skip/subtitles; не менять общий NPC dialogue.
4. Добавить небольшие server-side narrative flags в team-save и безопасные события после подтверждённой доставки.
5. Затем 6–10 опциональных текстовых NPC-реакций и visual changes HUB; новый прогресс не должен требовать их просмотра.
6. Устроить короткий соло и Host+Client smoke pass.

**Открытые риски:** в текущих mission assets различается `artifactCount`, у 3–5 островов нет производственных сцен; у короля нет подтверждённого runtime full-body dialogue/cinematic rig. Не заявлять, что эти условия уже выполнены.
